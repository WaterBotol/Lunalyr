# Milestone 3: the wallpaper with Editorial, Spoken and the gradient

**Status:** done on this PC; a few checks need the owner (real players, Extend mode, 280 Hz, battery). Test build:
`C:\dev\Lunalyr Windows Test Builds\Lunalyr Windows Test Build 3\`.

## What works

- **The real wallpaper**, behind the desktop icons on every monitor the engine finds: the render engine
  (`src/Lunalyr.Render`) with one swap chain per monitor on the GPU that drives it, frame caps (60 fps by default),
  and pausing while the desktop is covered, a full-screen app is in front, or battery saver is on.
- **Two backgrounds**, picked by `backgroundMode` in `settings.json`: `gradient` (the album colour field, default)
  and `colourOnly` (the Mac's straight album gradient; `colour` works too). Both fade from one album to the next.
- **Two compositions**, picked by `lyricComposition`: `editorial` and `spoken`, with word-by-word reveals, held
  notes, backing vocals, duet lines held under the next line, instrumental breaks (three dots), wrapping lines,
  right-to-left scripts, colour emoji, plain lyrics and calm status lines.
- **Album colours.** On each track change the app reads the player's cover, works out its colours off the UI thread
  and colours the background with them. The lyrics take pastel tints of the same colours, as the Mac's default
  "Album drift" does. Covers are cached per track. A cover that arrives a moment after the title is still picked up,
  and a track without a cover gets the Mac's default colours.
- **A softer text backing.** Over bright, contrasty covers the shade behind the lyrics used to show as a dark
  rectangle with lighter edges. It is now feathered widely: full strength where lyrics are set, with no visible edge
  or corner (re-rendered: [`docs/previews/gradient/gradient-contrast-*.png`](../previews/gradient/); the earlier
  render with the rectangle is in git history, before commit 6ef9467).
- **Readings** of Japanese lyrics come from the bundled dictionary and show below the lines.
- **`--demo`**: a silent built-in player with two invented songs, an English one and a Japanese one with readings.
  They have word-timed lyrics and covers painted in code, and loop in real time. Nothing plays, nothing is looked up
  online, no real player is touched, and it keeps its own settings folder (see `docs/APP-SHELL.md`, "Demo mode").
- **`--stats <file>`** writes frame statistics on quitting, for `tools/measure.ps1`.

- CPU is the same as the spike's even though the real compositions and backgrounds do far more than its test line.
  Render-thread time is unchanged too.
- Memory is about 25 MB higher. That is the app around the renderer: the lyric and readings services, the expanded

### A flaky lyric-core test (not changed by this milestone; a product question)

`LyricServiceEndToEndTests.LrclibLosesItsLeadWhenTwoOtherSourcesAgreeAgainstItsTiming` sometimes fails. LRCLIB
wins instead of Lyrics+. This branch changes nothing under `src/Lunalyr.Core` or `tests/Lunalyr.Core.Tests`.
- **Cause, confirmed.** In a throwaway copy of the test, Lyrics+ and NetEase answered 300 ms after LRCLIB, and the
  test failed every time.
- **Mechanism, from reading the code.** LRCLIB's word timing is shown as soon as no pending source could outrank it
  on its own (`LyricRanking.IsSettled` / `CouldBeat`). Agreement against its timing only exists once the others
  have answered, and the later pairwise upgrade check (`LyricPublication.IsUpgrade`) doesn't bring it back in.
- **So arrival order decides** whether "LRCLIB loses its lead when two other sources agree" holds. That is one of
  the rules in AGENT-RULES, so it's a question for the lyric core, not test noise.
- **How often.** Alone, the Core assembly failed 1 time in 15 and the end-to-end class 0 times in 15. In full
  solution runs it failed 2 times in 7.

## What's left

- **Other compositions** (Scattered, Constellation, Echo, Cascade, Cutout…) and other backgrounds (pattern,
  shader, visualiser, desktop picture, custom picture, music video). Unknown values show Editorial / the gradient.
- **The settings UI** for all of this (composition, background, readings below/instead, lyric size, colours): for
  now it's `settings.json`. The real settings pages and the tray flyout are milestone 5.
- **Lyric colours drift per line, not per frame.** The Mac redraws every glyph each frame as its ink drifts; here
  the colours are baked when a line is set, keyed to the line's start in the song. The other colour modes (Sung
  sweep, Music reactive, Custom gradient, Static white) and the highlight tiles are not wired yet.
- **Backing vocals tagged `x-bg` in Apple-style TTML** don't seem to reach the compositions (no `ttm:role` handling
  in the TTML parser); parenthesised ones do. This should be checked against the Mac's parser.
- **A cover is cached per track once read.** If a player hands over the previous song's cover for a moment, those
  colours would stay for that track; the owner's live check will show whether players do this.
- **Japanese readings split some verbs**: 見ていた reads "mite ita" even when it is one timed word. That comes from
  the readings service, not the wallpaper.
- Slow frames (above); Extend mode, mixed DPI, 280 Hz and battery checks (below).

## What the owner should try with real music

Quit any test build first, then run the normal build (`Lunalyr.exe`, or `--no-playback` to be sure it never sends
a command to the player) and play music in Spotify, Apple Music or a browser:

1. **Track changes.** The lyrics, the background colours and the lyric colours should all change with the song,
   with one smooth background fade. Watch for colours that belong to the *previous* song: some players publish the
   new title before the new cover.
2. **Songs without a cover**, such as local files or some browser tabs, should get the default colours (the Mac's
   fallback palette).
3. **Japanese, Chinese and Korean songs** should show readings below the lines. To switch them off, set
   `"romanizationDisplay": "off"` in `settings.json` (with Lunalyr quit).
4. **Spoken and the colour background:** set `"lyricComposition": "spoken"` and `"backgroundMode": "colourOnly"`
   in `%LOCALAPPDATA%\Lunalyr\settings.json` while Lunalyr is not running (it reads the file at start-up).
5. **Extend mode** (Settings › System › Display): both monitors should get their own wallpaper. Try the panel's
   280 Hz mode with the default 60 fps cap and with `"animationRate": 0`.
6. **On battery with energy saver on**, the wallpaper should pause.
